# n2(N2 CMS)

[共通の準備](setup.md) が終わっている前提です。コマンドは、とくに書いていなければリポジトリの一番上のフォルダーで実行します。
[コーパスの一覧に戻る](README.md)

このページの手順は記録(2026-10-11)の手順です。この手引きのためには動かしていません(コマンドはスクリプトと照らし合わせて確かめました)。

## 1. 概要

- **どんなアプリ**: CMS(Web Forms、C#)。DB は SQLite(`App_Data\n2.sqlite.db`)。
- **大きさ**: 取得 66 MB、変換の出力 5.1 GB、元のビルド 1.2 GB。
- **特別なこと**: 元のビルドの後に、リポジトリのセットアップの手順(`build\n2.proj;Templates-PrepareDependencies`)が要ります。SQL Server は要りません。

## 2. 前提

| もの | 要るか |
|---|---|
| Visual Studio Build Tools(元のビルド) | **要る**([共通の準備の手順 6](setup.md#手順-6-visual-studio-build-tools-を入れる元のビルドが要るコーパスだけ)) |
| SQL Server Express | 要らない(SQLite) |
| インストーラー | N2 のインストーラー(管理者のパスワード → テーブル → サンプルのコンテンツ)。`n2-install.ps1` が動かす |
| Docker Desktop | Linux で動かすとき |
| ディスク | 取得 66 MB、変換の出力 5.1 GB、元のビルド 1.2 GB |

## 3. 手順

### 3.1 取得する

```powershell
.\corpora\fetch.ps1 -Only n2
```

確認: 「すべて取得できました。」と出て、`corpora\work\n2cms-master` ができます。

### 3.2 変換する(元のビルドを含む)

**コマンドラインで(まとめて変換。こちらを勧めます)**: 元のビルドの後の手順はスクリプトが指定済みです。

```powershell
.\experiments\wf4c\convert-corpora.ps1 -Only n2
```

確認: `=== n2 BUILD OK ...` と出て、`experiments\wf4c\n2\site\bin\N2.Templates.dll` があります。
`snapshot` の違いで失敗扱いになるときは [共通の準備の 10.8](setup.md#108-変換がdiffer-from-their-snapshotで失敗する)。

**Studio で**([使い方](setup.md#41-studio画面)):

| 欄 | 値 |
|---|---|
| プロジェクト | `<リポジトリ>\corpora\work\n2cms-master\src\WebForms\WebFormsTemplates\N2.Templates.csproj` |
| リポジトリのフォルダー | `<リポジトリ>\corpora\work\n2cms-master` |
| 構成 | `Release` |
| ステップ 4 | 「元のアプリをそのビルド手順でビルドし、配置されるサイトから組み立てる」にチェック(自動判定で入ります)。**「追加の手順」に `build\n2.proj;Templates-PrepareDependencies` と書きます** |

**コマンドラインで(変換器を直接)**: `convert-corpora.ps1` と同じ値です。

```powershell
.\converter.ps1 corpora\work\n2cms-master\src\WebForms\WebFormsTemplates\N2.Templates.csproj --out C:\work\n2-out --root corpora\work\n2cms-master --build-original auto --original-step "build\n2.proj;Templates-PrepareDependencies" --culture-profile experiments\wf4c\_culture\culture-profile.json
```

### 3.3 インストールする(Windows で起動もする)

```powershell
.\experiments\wf4c\n2-install.ps1
```

`n2-install.ps1` は、サイトを起動し(ポート 5096)、次を順に行います: 管理者のパスワード(既定 `N2admin!2026`)→ ログイン → テーブル → サンプルのコンテンツ → `/`。サイトは動いたまま残ります。

- ページの要求には `experiments\wf4c\_linux\page.ps1`(Git に入っています)を使います。
- 確認: 最後の `--- the site` の後に、`/` のコンテンツ付きの内容が出ます。

### 3.4 Windows で動かす

`n2-install.ps1` のあとは、サイトが動いているので **http://localhost:5096/** を開くだけです。自分で起動するときは:

```powershell
cd experiments\wf4c\n2\site
..\..\supervise.ps1 -Dll bin\N2.Templates.dll -Port 5096
```

止め方は [共通の準備の 6.2](setup.md#62-止める)。

### 3.5 開くページとログイン

| ページ | 見えるもの |
|---|---|
| `/` | トップ(サンプルのコンテンツ) |
| `/N2/` | 管理画面。ログインへ転送される(302) |

管理者は **`admin` / `N2admin!2026`**(`n2-install.ps1` の既定。`-Password` で変えられます)。

### 3.6 Linux で動かす

Docker Desktop を起動しておきます。サイトを残してコンテナで起動し、同じインストールをコンテナに対して行います(ポート 5098)。

```powershell
.\experiments\wf4c\run-linux-site.ps1 -Site n2\site -Dll N2.Templates -Keep
.\experiments\wf4c\n2-install.ps1 -Port 5098 -Running
```

- `-Running` は「サイトは起動済み」という意味です(`n2-install.ps1` は起動しません)。
- 確認: `n2-install.ps1` の最後に `/` のコンテンツが出ます。ブラウザーで http://localhost:5098/ も開けます。

## 4. 期待される結果

| 何を | 結果 | 出どころ |
|---|---|---|
| Windows | インストーラー完了、トップがコンテンツ付き、`/N2/` はログインへ(302) | 記録 2026-10-11(Windows のトップ 200 は 2026-10-27 に再確認) |
| Linux | 同じ | 記録 2026-10-11 |
| 変換レポート | スタブ 6 件(`IDataContractSurrogate`、`AssemblyBuilder.Save` など) | 記録 |

記録のあとにパッケージの版が上がっています(今は `1.6.5-w2l.27`)。同じ結果になるはずですが、確かめてはいません。

## 5. 既知の差・制限

- インストーラーは SQLite の DB を書き換えます。Windows と Linux の両方で試すときは、変換直後のサイトを写しておきます。
- リポジトリの DB にはもともとサンプルのサイトが入っているので、`/` がそのまま表示されることもあります。
- IIS で記録した正解は無いので、自動の比較はできません。

## 6. うまくいかないとき

- **元のビルドが失敗する**: Studio では「追加の手順」の書き忘れがないか確かめます。ログの見方は [共通の準備の 10.2](setup.md#102-元のビルドが失敗する)。
- **インストールの途中で応答が無い**: 管理者のパスワードを設定すると web.config が変わり、アプリが再起動します(スクリプトは 5 秒待ちます)。もう一度開けば答えます。
- **もう一度インストールしたい**: 変換直後の写しに戻すか、`.\experiments\wf4c\convert-corpora.ps1 -Only n2` で変換し直します。
- 共通のことは [共通の準備の 10](setup.md#10-うまくいかないとき)。

## 7. 片付け

```powershell
Get-NetTCPConnection -LocalPort 5096 -State Listen -ErrorAction SilentlyContinue | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
docker rm -f w2l-site-n2                 # run-linux-site.ps1 -Keep で残したコンテナ
```

そのあと、Docker Desktop を止めて `wsl --shutdown`([共通の準備の 9](setup.md#9-後片付け))。
