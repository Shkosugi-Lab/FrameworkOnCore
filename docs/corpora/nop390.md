# nop390(nopCommerce 3.90、MVC 5)

[共通の準備](setup.md) が終わっている前提です。コマンドは、とくに書いていなければリポジトリの一番上のフォルダーで実行します。
[コーパスの一覧に戻る](README.md)

このページの手順は記録(2026-10-11)の手順です。この手引きのためには動かしていません(コマンドはスクリプトと照らし合わせて確かめました)。

## 1. 概要

- **どんなアプリ**: 最後の MVC 5 版の nopCommerce(EC サイト、C#。プラグイン、Autofac、AutoMapper、EF6)。
- **大きさ**: 取得 334 MB、変換の出力 2.0 GB、元のビルド 0.8 GB。
- **特別なこと**: 元のビルドがプラグインを `Plugins` に置きます。そのため、元のアプリをソリューションでビルドし、配置されるサイト(`src\Presentation\Nop.Web`)から組み立てます。IIS で記録した正解は **ありません**(比べる道具は使えず、ページを開いて確かめます)。

## 3. 手順

### 3.1 取得する

元の GitHub のリポジトリから、次の版を取ります(このページの結果は、この版で出したものです)。

| | |
|---|---|
| リポジトリ | <https://github.com/nopSolutions/nopCommerce> |
| 版 | タグ `release-3.90`(コミット `12d1f0139149a9d6e84964d325d62bae6ac748f6`、2017-03-15) |
| ライセンス | nopCommerce Public License Version 3.0(GPLv3 に「powered by nopCommerce」の表示の条件を加えたもの)。[LICENSE.md](https://github.com/nopSolutions/nopCommerce/blob/release-3.90/LICENSE.md) |
| フォルダーの名前 | `nopCommerce-release-3.90`(この名前にしておくと、このページのパスがそのまま使えます) |

置く場所はどこでも構いません。ただし:

- **比較のスクリプトを使う場合は `corpora\work\nopCommerce-release-3.90` に置きます**(`convert-corpora.ps1`、`corpora\build-original.ps1`、`convert-corpora.ps1` の出力を使う `verify-windows.ps1`・`run-linux.ps1` は、このパスを前提にしています)。
- パスの長さ: 元のビルド(NuGet の復元)のあと、フォルダーの中でいちばん深いファイルは 134 文字です。.NET Framework の MSBuild は Windows の MAX_PATH(260 文字)を超えるパスを扱えないので、**フォルダー自体のパスを 124 文字以内**にします(`<リポジトリ>\corpora\work\nopCommerce-release-3.90` や `C:\corpora\nopCommerce-release-3.90` なら収まります)。

**近道(`fetch.ps1`)**: 下と同じこと(ダウンロード、展開、フォルダーの名前)をして、`corpora\work` に置きます。取得元(リポジトリとタグ・コミット)も表示します。

```powershell
.\corpora\fetch.ps1 -Only nop390
```

確認: 「すべて取得できました。」と出て、`corpora\work\nopCommerce-release-3.90` ができます。

**A. GitHub の画面から(ZIP)**

1. <https://github.com/nopSolutions/nopCommerce/tree/release-3.90> を開き、「Code」→「Download ZIP」を押します(直接のリンク: <https://github.com/nopSolutions/nopCommerce/archive/refs/tags/release-3.90.zip>)。
2. ZIP を展開します。中の `nopCommerce-release-3.90` フォルダーがコーパスです。

**B. git で**(置きたい場所の一つ上のフォルダーで)

```powershell
git clone --filter=blob:none -c core.autocrlf=false -c core.eol=lf https://github.com/nopSolutions/nopCommerce.git nopCommerce-release-3.90
git -C nopCommerce-release-3.90 checkout 12d1f0139149a9d6e84964d325d62bae6ac748f6
```

`-c core.autocrlf=false -c core.eol=lf` は、改行を ZIP(と `fetch.ps1`)と同じにするためです。付けないと Git for Windows の既定(`core.autocrlf=true`)でテキストの改行が CRLF に変わり、ファイルの中身が ZIP と違ってしまいます(wt では 178 ファイル)。`.git` フォルダーが増えるのは構いません。
`--filter=blob:none` は、リポジトリが大きい(全体で約 1690 MB)ので、そのコミットのファイルだけを取るためです。

**Studio・変換器に渡すフォルダー**: 「リポジトリのフォルダー」(`--root`)は置いたフォルダー(`nopCommerce-release-3.90`)、「プロジェクト」はその中の `src\Presentation\Nop.Web\Nop.Web.csproj` です。`corpora\work` 以外に置いたときは、3.2 以降の `corpora\work\nopCommerce-release-3.90` を置いた場所に読み替えます。

### 3.2 変換する(元のビルドを含む)

### 3.3 Windows で動かしてインストールする

```powershell
Start-Service 'MSSQL$SQLEXPRESS'      # 管理者の PowerShell で
cd experiments\wf4c\nop390\site
..\..\supervise.ps1 -Dll bin\Nop.Web.dll -Port 5096
```

**http://localhost:5096/** を開くとインストールの画面が出ます。SQL Server(`.\SQLEXPRESS`)を選び、**サンプルのデータ付き** でインストールします。
インストールのあとはアプリが再起動します。止め方は [共通の準備の 6.2](setup.md#62-止める)。

### 3.4 開くページ

- 店頭のトップ(`/`)と商品・カテゴリの画面、商品の画像、カートへの追加(AJAX)。
- 管理画面(インストールの画面で入れた管理者のメールとパスワードでログイン)と、その一覧。

### 3.5 Linux で動かす

変換が書いた Dockerfile のイメージで動かし、空の DB からインストーラーを通します(記録 2026-10-01・10-11。SQL Server はコンテナ)。やり方は [共通の準備の 7.1](setup.md#71-a-変換が書いた-dockerfile)、SQL Server のコンテナの作り方は [wt のページの 3.7](wt.md#37-linux-で動かす) と同じです。

```powershell
docker network create foc-net
docker run -d --name foc-sql --network foc-net -e ACCEPT_EULA=Y -e "MSSQL_SA_PASSWORD=Foc_local_Passw0rd" mcr.microsoft.com/mssql/server:2022-latest
cd experiments\wf4c\nop390
docker build -t nop390 .
docker run -d -p 8080:8080 --name nop390 --network foc-net nop390
```

- **http://localhost:8080/** を開くとインストールの画面が出ます。DB の接続先はインストールの画面で入れます。コンテナの中からは `.\SQLEXPRESS` は見えないので、SQL Server のコンテナの名前(上の例では `foc-sql`)か `host.docker.internal` と、SQL Server の認証(上の例では `sa` / `Foc_local_Passw0rd`)を入れます。
- 上のコマンドの名前(`nop390`、`foc-net`、`foc-sql`)は、この手引きの例です(記録には実行したコマンドそのものは残っていません)。

## 5. 既知の差・制限

- IIS で記録した正解はありません。比べる道具は使えず、ページを開いて確かめます。
- サンプルの「Apple MacBook Pro」は最小の数量が 2 です(1 ではカートに入りません。アプリの仕様)。

## 6. うまくいかないとき

- **curl などで試すと、カートとログインが断られる**: nopCommerce 3.90 は curl の User-Agent を検索エンジンとみなします。ブラウザーで、またはブラウザーの User-Agent を付けて要求します。
- **もう一度インストールしたい**: インストーラーは `App_Data` を書き換えます。変換直後のサイトを写しておいて戻すか、`.\experiments\wf4c\convert-corpora.ps1 -Only nop390` で変換し直します。
- **コンテナからインストールの画面で DB につながらない**: `.\SQLEXPRESS` は見えません。3.5 のとおり、SQL Server のコンテナの名前か `host.docker.internal` と SQL Server の認証を使います([共通の準備の 10.3](setup.md#103-sql-server-につながらない))。
- 共通のことは [共通の準備の 10](setup.md#10-うまくいかないとき)。

## 7. 片付け

```powershell
Get-NetTCPConnection -LocalPort 5096 -State Listen -ErrorAction SilentlyContinue | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
docker rm -f nop390 foc-sql
docker network rm foc-net
Stop-Service 'MSSQL$SQLEXPRESS'          # 管理者の PowerShell で
```

そのあと、Docker Desktop を止めて `wsl --shutdown`([共通の準備の 9](setup.md#9-後片付け))。
